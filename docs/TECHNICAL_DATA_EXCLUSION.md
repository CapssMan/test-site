# SkillCheck — исключение технических результатов

Статус: решение владельца от 26 июля 2026 года.

## Решение

Существующие production smoke-результаты не удаляются. Они сохраняются как техническая история разработки и не считаются кандидатами, пилотной выборкой, рейтингом или доказательством качества тестов.

Известный набор кодов:

- `DEV-Z2VK8`
- `DEV-E94Y8`
- `DEV-EZ3BY`
- `FA-5DU43`
- `DEV-B4ABJ`
- `DEV-TVENX`
- `DEV-7S2N2`
- `FA-X5P66`
- `FA-LDUB2`

Из-за ранее прерванной операции удаления фактическое число присутствующих строк может быть меньше девяти. Классификация применяется по коду ко всем сохранившимся строкам.

## Контракт аналитики

- Admin Build `2026.07.31.3` по умолчанию исключает весь известный набор и любые результаты `dev-quick` из таблицы, метрик и диаграмм.
- Отдельный переключатель явно возвращает технические строки и помечает их как «Технический».
- Любые будущие рейтинг, экспорт, pilot analysis и employer analytics обязаны использовать ту же классификацию по точному коду. Фильтрации только по `testId=dev-quick` недостаточно.
- Защищённая диагностика показывает физическое число строк хранилища; оно не равно числу реальных кандидатов.
- Коды результатов не переиспользуются и не присваиваются реальным прохождениям вручную.

## Граница решения

Это исключение относится только к известным данным владельца/разработки. Оно не отменяет:

- право реального кандидата запросить удаление;
- защищённый preview/confirmed deletion workflow;
- утверждение сроков хранения и legal hold;
- запрет ручного редактирования production JSON.

До пилота владелец проверяет, что при выключенном переключателе технических данных базовые метрики не содержат известных smoke-кодов. Наличие этих строк больше не считается самостоятельным blocker пилота; внешние SME, legal/retention и owner sign-off остаются обязательными.
