# SkillCheck — что осталось владельцу до первого пилота

Обновлено: 31 июля 2026 года.

Это рабочая памятка, а не юридическое заключение. Не помещать в Git домашний адрес, телефон, подпись, данные Госуслуг, пароли, токены, answer key и закрытые заключения.

## На владельце: три результата

### 1. Независимая проверка пяти банков

Самостоятельно выбрать преподавателей ВУЗа или практиков по соответствующим направлениям и передать им только их reviewer-пакеты по `SME_REVIEW_HANDOFF.md`. Автоматическая рассылка от проекта запрещена.

Для Codex достаточно безопасной сводки по каждому банку: `APPROVED`, `APPROVED WITH FIXES` или `REJECTED`, количество блокирующих и неблокирующих замечаний. ФИО, подписи, answer key и сами закрытые книги передавать не нужно.

После замечаний Codex исправит вопросы, выпустит новую версию банков, повторит полный аудит 240 вопросов и опубликует только после подтверждения владельца.

### 2. Уведомление Роскомнадзора и реквизиты оператора

До начала обработки реальных кандидатов владелец заполняет официальную форму и сохраняет подтверждение подачи либо документированное основание неприменимости. Из проекта уже известны:

- оператор: физическое лицо, Кириллов Кирилл Сергеевич;
- регион: Москва;
- контакт по персональным данным: `skillcheck.project@yandex.ru`;
- основной контур: Yandex Object Storage, API Gateway, Cloud Functions и Managed Service for YDB в российском контуре;
- планируемая трансграничная передача для реального candidate-потока: отсутствует; интерактивные GitHub-страницы переводят пользователя на основной Yandex-сайт, а GitHub-origin не разрешён candidate API;
- специальные и биометрические категории проектом не запрашиваются;
- автоматизированная обработка применяется для проведения теста, серверного подсчёта результата, защиты попытки, хранения и удаления;
- отдельная цель добровольного рейтинга действует только после отдельного согласия на распространение.

Рабочие цели обработки:

1. Провести контролируемую профессиональную оценку и выдать проверяемый результат.
2. Обеспечить безопасность, ограничение повторов, восстановление отправки и выполнение запросов субъекта.
3. По отдельному добровольному согласию опубликовать ограниченный профиль в рейтинге.

Основные категории данных: ФИО, email, необязательный Telegram, уровень английского, опыт и источник приглашения; ответы, время и техническая телеметрия; тест, версия банка, результат, код и технические идентификаторы/хеши; для рейтинга — псевдоним, тест, балл, дата, статус проверки и место.

Основные действия: сбор, запись, систематизация, накопление, хранение, уточнение, извлечение, использование, псевдонимизация, блокирование, удаление и уничтожение с автоматизацией. Распространение относится только к добровольному рейтингу.

Утверждённые сроки: приглашение и техническая попытка — до 90 дней; ответы, результат, отчёт и технический журнал — до 365 дней; резервные объекты — до 30 дней; временные staging-объекты — до 1 дня; профиль рейтинга — до отзыва, но не более 365 дней без нового подтверждения.

Владелец заполняет лично и не передаёт Codex: точный адрес для формы, телефон/контакт ответственного, дату начала обработки, условие прекращения, сведения для входа и подписи. Домашний адрес не публиковать на сайте автоматически: отдельно определить обязательный публичный объём и передать Codex только уже утверждённый публичный текст.

После подачи передать Codex только безопасный итог: `подано`, дата, номер/статус без персональных реквизитов; либо `не требуется` вместе с основанием, проверенным по официальной форме или профильной консультации.

### 3. Финальное решение владельца

После SME и legal результата подтвердить:

- размер первой волны: 10–30 завершённых прохождений;
- непубличный invite-only режим;
- ответственного за обращения и остановку пилота;
- решение `GO`, `LIMITED GO` или `NO-GO`.

Только после явного `GO` Codex отдельно откроет legal gate, проверит систему, затем отдельным действием откроет issuance. Эти переключатели не открываются вместе с обновлением кода.

## На стороне Codex

- поддерживать российский production-контур, проверки, резервный статический GitHub и закрытые gates;
- внести подтверждённые SME-исправления новой версией банков;
- обновить policy/consent только утверждёнными публичными реквизитами;
- выполнить финальный CI, live-readiness и owner smoke;
- после явного `GO` открыть gates по одному, проверить первый пилот и подготовить аналитику без технических результатов.

Пока три результата владельца не получены, новых обязательных продуктовых этапов перед пилотом нет. Рейтинг, тесты, админка, российское хранение, сроки удаления и техническая блокировка запуска уже реализованы.
