# SkillCheck — privacy checklist оператора

Обновлено: 31 июля 2026 года.

Это инженерный контрольный список, а не юридическое заключение. Технический российский контур и сроки хранения уже реализованы; реальные кандидаты остаются заблокированы двумя независимыми gate.

## Обязательные условия до первого кандидата

До закрытия пунктов сохранять `LEGAL_PILOT_APPROVED=false` и `ATTEMPT_ISSUANCE_ENABLED=false`. `RETENTION_AUTOMATION_ENABLED=true` уже утверждён и включён отдельно.

- [x] ФИО оператора и проверенный email опубликованы в policy/consent.
- [x] Сроки хранения утверждены владельцем и применены через YDB TTL/Object Storage lifecycle.
- [x] Основной candidate-поток перенесён в российский Yandex Cloud; GitHub-origin не разрешён API.
- [x] Банки технически и содержательно ротированы выпуском v4.
- [ ] Владелец подал уведомление Роскомнадзора или зафиксировал проверенное основание неприменимости и решение по отсутствию трансграничной передачи.
- [ ] Определён окончательный обязательный публичный состав реквизитов и адреса оператора.
- [ ] Все пять банков получили независимый человеческий SME verdict; блокирующие замечания устранены новой версией.
- [ ] В закрытом owner-журнале зафиксированы канал обращений, ответственный, stop conditions и финальное `GO`.

Подробный список действий владельца: `OWNER_ACTIONS.md`. Техническая готовность не закрывает внешние пункты автоматически.

## Перед изменением потока данных

- [ ] описаны цель, категории данных, получатели и срок;
- [ ] новое поле действительно необходимо;
- [ ] privacy/consent версии обновлены согласованно с backend contract;
- [ ] обязательное согласие не объединено с добровольным рейтингом или будущей передачей работодателю;
- [ ] тесты legal/privacy, deletion, security и полный `npm test` зелёные;
- [ ] GitHub, иностранный SaaS или новый платный сервис не добавлен в реальный candidate-поток без отдельного решения владельца.

## Перед созданием приглашения

- [ ] оба gate открыты отдельными подтверждёнными действиями;
- [ ] есть утверждённая цель, конкретный тест и лимит пилота;
- [ ] используется минимально необходимый email; телефон не собирается;
- [ ] bearer-код не помещается в query string и передаётся кандидату по закрытому каналу;
- [ ] доступны актуальные privacy notice, отдельное согласие и подтверждение 18+;
- [ ] передача работодателю не включена без отдельного основания и точного получателя;
- [ ] нет дублирующего активного приглашения без документированной причины.

## Во время обработки

- [ ] доступ к Yandex Cloud, YDB, Object Storage и админке есть только у владельца и действующих операторов;
- [ ] пароли, ключи, salts, signing secrets и закрытые диагностики не попадают в Git, почту или публичные задачи;
- [ ] TXT-отчёт и ручные выгрузки открываются только по служебной необходимости и имеют срок удаления;
- [ ] рейтинг публикуется только по отдельному opt-in и удаляется по management token или подтверждённому запросу;
- [ ] SkillCheck не используется как единственное основание найма или отказа;
- [ ] время ответа и уходы со вкладки остаются `client-reported-unverified` и не уменьшают балл.

## Запрос субъекта данных

1. Зафиксировать дату, канал, тип запроса и ответственного в закрытом журнале.
2. Проверить личность пропорциональным способом; не подтверждать наличие записи по одному непроверенному email.
3. Найти запись по коду результата и разрешённым внутренним идентификаторам.
4. Выполнить preview удаления, проверить scope и затем подтверждённую операцию из админки.
5. Не редактировать YDB/Object Storage вручную; при частичном сбое использовать deletion recovery.
6. Проверить result, attempt/session/invite, отчёт, профиль рейтинга и применимые backup-объекты.
7. Зафиксировать результат без хранения лишних данных.

## Инцидент

- [ ] немедленно закрыть issuance;
- [ ] определить категории, период и системы;
- [ ] ротировать скомпрометированный credential без публикации старого или нового значения;
- [ ] проверить Yandex Cloud audit/diagnostics, YDB, Object Storage и историю Git;
- [ ] сохранить только минимальные доказательства;
- [ ] определить применимые уведомления и сроки;
- [ ] после устранения выполнить CI, live-check и отдельное решение `GO/NO-GO`.

## Регулярная проверка владельца

- [ ] контакты, policy/consent versions и список доступов актуальны;
- [ ] gates имеют ожидаемое значение;
- [ ] `RETENTION_AUTOMATION_ENABLED=true`, TTL/lifecycle и backup-cleanup подтверждены;
- [ ] просроченные ручные выгрузки уничтожены;
- [ ] запросы субъектов и инциденты не просрочены;
- [ ] технические smoke-строки исключены из обычной аналитики;
- [ ] ответственный может быстро закрыть issuance и выполнить rollback.

## Закрытый журнал решения

Вне публичного репозитория сохранить дату и ответственного, цель, Git commit и версии, состояние gates, результаты CI/live-check, открытые риски, объём пилота и итог `GO`, `LIMITED GO` или `NO-GO`.

Связанные документы: `OWNER_ACTIONS.md`, `PRE_PILOT_INPUTS.md`, `LEGAL_PRIVACY_REVIEW.md`, `SME_REVIEW_HANDOFF.md`, `DATA_DELETION.md`, `OPERATIONS.md`.
