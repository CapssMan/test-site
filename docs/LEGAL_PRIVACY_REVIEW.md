# SkillCheck: инженерная legal/privacy-сверка MVP

Дата технической сверки: 29 июля 2026 года.

Это инженерная сверка фактического потока данных с действующими публичными требованиями. Она не является юридическим заключением и не закрывает обязанности оператора автоматически.

## Вывод

Технический контур приведён в согласованное fail-closed состояние:

- отдельное согласие версии `skillcheck-pd-consent-2026-07-29-v4` подтверждается до создания сессии и фиксируется по серверному времени;
- отдельное необязательное согласие на распространение версии `skillcheck-ranking-public-2026-07-29-v2` ограничивает публичные поля рейтинга;
- основной сайт, API, функции, результаты, журнал и рейтинг работают в российском контуре Yandex Cloud;
- GitHub Pages, Google Apps Script и Яндекс Диск остаются только техническим rollback и не используются для реальных кандидатов;
- сроки хранения технически применены: `RETENTION_AUTOMATION_ENABLED=true`, YDB TTL и Object Storage lifecycle;
- передача контактов, отчёта или результата работодателю остаётся выключенной;
- `LEGAL_PILOT_APPROVED=false` и `ATTEMPT_ISSUANCE_ENABLED=false` не позволяют принять реального кандидата.

Реальный пилот остаётся **NO-GO**. Не закрыты: допустимый состав публичных реквизитов и адреса оператора, подача или подтверждённая неприменимость уведомления Роскомнадзора, внешняя проверка документов и независимый SME review банков.

## Основания сверки

- [Статья 9 № 152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/6c94959bc017ac80140621762d2ac59f6006b08c/) требует конкретного, информированного и однозначного согласия, оформленного отдельно от другой подтверждаемой информации.
- [Статья 18 № 152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/cbf4e15b7c330f9372e876cdf2bc928bad7950ef/) ограничивает использование зарубежных баз при сборе данных граждан РФ через интернет.
- [Статья 22 № 152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/7b0fbcf8649ad8817c8b9986984c0d83288e5778/) устанавливает уведомление уполномоченного органа до начала обработки, кроме предусмотренных законом исключений.
- Формы уведомлений утверждены [приказом Роскомнадзора № 180](https://publication.pravo.gov.ru/Document/View/0001202212150022).
- Требования к подтверждению уничтожения утверждены [приказом Роскомнадзора № 179](https://publication.pravo.gov.ru/Document/View/0001202211290008).
- Требования к согласию на распространение установлены [приказом Роскомнадзора № 18](https://www.consultant.ru/document/cons_doc_LAW_382687/37752db178121f5758180844db843703ca3f46e5/).

Роскомнадзор отдельно разъясняет, что оператором может быть физическое лицо и что сайт, собирающий данные, может образовывать обязанности оператора: [официальное разъяснение](https://82.rkn.gov.ru/directions/pers/p15375/).

## Фактический production-поток

| Этап | Данные | Российское место/форма |
|---|---|---|
| Открытие | статические страницы и display-only банки | публичный Yandex Object Storage |
| До начала | invite и email | `sessionStorage` текущей вкладки до 30 минут |
| Начало | email, fingerprint, версия и факт согласия | Yandex API Gateway/Cloud Functions; в YDB пишутся HMAC/hash и server time |
| Прохождение | ответы, время, tab switches, attempt token | память/`sessionStorage` максимум 6 часов |
| Результат | псевдонимизированная сводка; полный отчёт только при passed | YDB и закрытый Object Storage |
| Рейтинг | псевдоним, направление, балл, дата, статус проверки | YDB; только после отдельного opt-in |
| Retention | active rows, отчёты, backups, staging | YDB TTL: 90/365 дней; Object Storage lifecycle: 1/30/365 дней |

Сводки с кодом результата являются псевдонимизированными, а не анонимными. Код результата не даёт публичный доступ к полному отчёту.

## Обязательный checklist владельца до legal gate

- [x] Опубликовать ФИО и рабочий email оператора; не публиковать избыточные статус НПД и регион.
- [x] Перенести активный candidate write-path и первичные базы в российский Yandex Cloud.
- [x] Утвердить и технически применить сроки хранения.
- [x] Реализовать отдельные versioned-согласия на тест и добровольный рейтинг.
- [x] Оставить передачу работодателю выключенной до отдельного согласия для конкретного получателя.
- [ ] Определить допустимый публичный адрес оператора и финальный состав реквизитов.
- [ ] Проверить применимость исключений и подать уведомление об обработке в Роскомнадзор, если оно требуется.
- [ ] Утвердить внутреннюю процедуру запросов, инцидентов, legal hold и подтверждения уничтожения.
- [ ] Получить внешнюю проверку финальных policy/consent и оснований по целям обработки.
- [ ] Получить независимый SME review/sign-off пяти банков v4.
- [ ] После документированного решения вызвать editor-only legal approval с точной версией согласия и только затем отдельно открыть issuance.

## Передача работодателю

Текущий disabled-control не является согласием. Backend отвергает `employerShareConsent:true`. Будущая прямая передача должна иметь отдельное основание и документ как минимум с конкретным получателем, целью, составом данных, сроком и способом отзыва.

## Граница инженерного результата

Присутствие российских сервисов, TTL, ссылок на закон и технических gate не означает `APPROVED`. До внешних решений сохраняются `LEGAL_PILOT_APPROVED=false` и `ATTEMPT_ISSUANCE_ENABLED=false`. В репозиторий не помещаются домашний адрес, закрытые комментарии специалиста, подписи или секреты.
