# Кабинет участника и аккаунт Яндекс ID

## Что реализовано

Реализован бесплатный контур идентификации кандидата через отдельное OAuth-приложение Яндекс ID и PKCE. Постоянный пароль SkillCheck не создаётся. Запрашиваются только уникальный идентификатор Яндекс и основной подтверждённый email; телефон, дата рождения, пол и фотография не запрашиваются.

OAuth-токен используется сервером один раз для получения разрешённых сведений и не сохраняется. В YDB записываются HMAC-хэши идентификатора и email, маскированный email, профиль, короткая сессия и связи с попытками. Токен сессии хранится только в `sessionStorage` браузера и действует не более 12 часов.

В новом account-first потоке кандидат выбирает любой из пяти тестов и входит через Яндекс. Ограничение повторного прохождения применяется по паре `profile_id + test_id`, поэтому очистка браузера, другой браузер или новая групповая ссылка не обходят 21-дневное окно. Аккаунт обязателен для новой попытки. Групповая ссылка необязательна и используется только как метка вуза, преподавателя или потока.

## Безопасное состояние по умолчанию

Миграции создают пять независимых переключателей:

- `account_registration_enabled=false` — новые аккаунты не создаются;
- `account_self_service_enabled=false` — самостоятельный выбор теста закрыт;
- `account_required_for_attempts=false` — старый маршрут не переключён на обязательный аккаунт;
- `profile_publication_enabled=false` — профиль нельзя открыть для поиска работодателями;
- `employer_contact_enabled=false` — контакты и запросы работодателей не выдаются.

Развёртывание backend и закрытой страницы кабинета не означает начало новой обработки. Каждый переключатель открывается отдельным решением после соответствующих документов и проверки.

## Модель заработка без продажи базы

SkillCheck не продаёт email и выгрузку кандидатов. Работодатель платит за доступ к фильтрам, подтверждённым результатам, shortlist и отправке запроса кандидату. Контакт раскрывается только если сам кандидат согласился и принял конкретный запрос. До отдельной реализации и юридического допуска `employer_contact_enabled` остаётся `false`.

## Развёртывание

`scripts/deploy-yandex-account-self-service.ps1 -OpenSelfService` временно закрывает выдачу новых попыток, требует отсутствие активных прохождений, применяет добавочную схему `014`, создаёт `assessment-v13` и `account-v2`, публикует страницы, проверяет live API и лишь затем открывает account-first режим. При любой ошибке выдача остаётся закрытой. Секреты не меняются и не выводятся; Lockbox, CDN, VM, платная почта и новые платные сервисы не подключаются.

`scripts/deploy-yandex-candidate-profile-v2.ps1 -Deploy` публикует совместимую страницу без преждевременного переключения Gateway, применяет добавочную схему `015` отдельными DDL/DML-запросами, создаёт `account-v3`, переключает только account-маршрут и проверяет live API. `account-v2` и старые runtime-версии не удаляются; платные сервисы не подключаются.
