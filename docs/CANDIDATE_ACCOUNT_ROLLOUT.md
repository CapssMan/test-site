# Кабинет участника и аккаунт Яндекс ID

## Что реализовано

Подготовлен бесплатный L2-контур идентификации кандидата через отдельное OAuth-приложение Яндекс ID и PKCE. Постоянный пароль SkillCheck не создаётся. Запрашиваются только уникальный идентификатор Яндекс и основной подтверждённый email; телефон, дата рождения, пол и фотография не запрашиваются.

OAuth-токен используется сервером один раз для получения разрешённых сведений и не сохраняется. В YDB записываются HMAC-хэши идентификатора и email, маскированный email, профиль, короткая сессия и связи с попытками. Токен сессии хранится только в `sessionStorage` браузера и действует не более 12 часов.

Ограничение повторного прохождения после входа применяется по паре `profile_id + test_id`, поэтому очистка браузера или новый код приглашения не создают новый профиль и не обходят 21-дневное окно. Старый L1-пилот по приглашениям продолжает работать без обязательного аккаунта.

## Безопасное состояние по умолчанию

Миграция создаёт три закрытых переключателя:

- `account_registration_enabled=false` — новые аккаунты не создаются;
- `profile_publication_enabled=false` — профиль нельзя открыть для поиска работодателями;
- `employer_contact_enabled=false` — контакты и запросы работодателей не выдаются.

Развёртывание backend и закрытой страницы кабинета не означает начало новой обработки. Каждый переключатель открывается отдельным решением после соответствующих документов и проверки.

## Что требуется от владельца до открытия регистрации

1. Создать отдельное OAuth-приложение Яндекс ID. Не переиспользовать приложение `SkillCheck Storage`.
2. Тип приложения: веб-сервис. Redirect URI должен в точности совпадать с `https://assessment-b1gafbjd3dlh-web.website.yandexcloud.net/account.html`.
3. Разрешения: только базовые сведения и email — scopes `login:info login:email`.
4. Передать Codex только `Client ID`. Секрет приложения не нужен для PKCE и передавать его нельзя.
5. Дополнить уведомление Роскомнадзору и публичную политику целями аккаунта, данными Яндекс ID, профилем, связью с результатами, сроком неактивности 12 месяцев и отдельной добровольной публикацией.
6. После подтверждения обновления документов отдельно разрешить открыть только регистрацию. Публичный поиск и работодатели останутся закрыты.

## Модель заработка без продажи базы

SkillCheck не продаёт email и выгрузку кандидатов. Работодатель платит за доступ к фильтрам, подтверждённым результатам, shortlist и отправке запроса кандидату. Контакт раскрывается только если сам кандидат согласился и принял конкретный запрос. До отдельной реализации и юридического допуска `employer_contact_enabled` остаётся `false`.

## Развёртывание

`scripts/deploy-yandex-candidate-account.ps1` применяет только добавочную схему, создаёт `assessment-v12` и `account-v1`, проверяет закрытые gates и переключает API Gateway лишь после успешного создания обеих версий. Lockbox, CDN, VM, платная почта и новые платные сервисы не подключаются. Секрет сессии создаётся локально при развёртывании, не выводится и не записывается в репозиторий.
